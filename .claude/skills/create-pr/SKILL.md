# PR 생성

PR 본문은 리뷰어의 시간을 아끼기 위해 존재한다. diff를 읽으면 알 수 있는 것을 반복하지 말고,
**diff를 읽어도 알 수 없는 것**(왜 이렇게 했는지, 무엇을 검증했는지, 무엇이 남았는지)을 써라.
이 관점이 아래 모든 절차의 이유다.

이 스킬은 파일을 쓰지 않는다. 조사하고, 본문을 만들고, `gh`로 PR을 생성한다.

## 1. 상태 파악

```bash
git branch --show-current
git remote -v
git log --oneline origin/HEAD..HEAD    # base 대비 커밋 (아래에서 base 확정)
git status --short
```

base 브랜치는 추측하지 말고 확인한다.

```bash
gh repo view --json defaultBranchRef --jq .defaultBranchRef.name
```

### 진행 전 확인

아래에 해당하면 PR을 만들지 말고 사용자에게 먼저 알린다.

- **현재 브랜치가 base 브랜치다.** PR을 만들 수 없다. 브랜치를 만들고 커밋을 옮길지 묻는다
- **커밋되지 않은 변경이 남아 있다.** 그 변경이 이 PR에 포함되어야 하는지 확인한다
- **base 대비 커밋이 없다.** 푸시할 것이 없다
- **원격에 브랜치가 없다.** `git push -u <remote> <branch>`가 필요하다. 푸시는 외부에
  드러나는 행위이므로 사용자 승인 없이 하지 않는다

## 2. 변경 내용 조사

```bash
git log <base>..HEAD --pretty='%s%n%b'   # 커밋 메시지 — 왜의 1차 출처
git diff <base>...HEAD --stat            # 규모 파악
git diff <base>...HEAD                   # 실제 내용
```

`...`(세 점)을 쓴다. 두 점은 base의 최신 커밋과 비교해 관계없는 변경까지 섞인다.

**커밋 메시지를 먼저 읽어라.** 이 저장소는 커밋 본문에 배경을 적는 관례가 있어
(`.claude/skills/commit/SKILL.md`), PR 본문의 "왜"는 대부분 거기에 이미 있다.
diff에서 무엇이 바뀌었는지 확인하고, 커밋 메시지에서 왜 바뀌었는지 가져와 합친다.

## 3. 검증 결과 수집

본문의 `## 검증` 섹션에는 **실제로 실행한 것만** 적는다. 추측해서 "통과"라고 쓰지 마라.
이미 이번 세션에서 실행해 결과를 아는 것이 있으면 그 결과를 쓰고, 없으면 지금 실행한다.

```bash
bun run test
bun run lint
bun run build
```

실패하면 실패한 대로 적는다. 실패를 숨긴 PR은 리뷰어가 같은 실패를 다시 발견하는 데
시간을 쓰게 만들고, 그때는 신뢰까지 잃는다. 실패가 이번 변경 때문이 아니라면
**그 근거**를 함께 적어라.

## 4. 본문 작성

`references/pr-template.md`를 읽고 그 구조와 작성 규칙을 따른다.
템플릿을 읽지 않은 채 기억으로 쓰지 마라.

세션에 커밋 속성(attribution) 지시가 주어져 있으면 그 지시대로 본문 끝에 트레일러를 붙인다.
지시가 없으면 붙이지 않는다.

## 5. 승인 후 생성

PR을 만들기 **전에** 사용자에게 보여준다.

- base와 head 브랜치, 대상 저장소
- PR 제목
- PR 본문 전문
- 1단계에서 걸린 것이 있으면 그 내용

그리고 승인을 기다린다. PR은 팀에게 알림이 가고 리뷰 요청이 붙는 **외부로 드러나는 행위**다.
사용자가 "PR 만들어줘"라고 말한 것은 행위의 승인이지, 아직 보지 못한 본문의 승인이 아니다.

승인을 받으면 stdin으로 본문을 넘긴다. 파일을 만들지 않아도 되고 따옴표 이스케이프 문제도 없다.

```bash
gh pr create --base <base> --head <branch> --title "<제목>" --body-file - <<'BODY'
## 요약

...
BODY
```

생성 후 반환된 URL을 사용자에게 전달한다.

### 하지 않는 것

- **머지하지 않는다.** 별도로 요청받았을 때만 한다
- **리뷰어·라벨·마일스톤을 임의로 지정하지 않는다.** 사용자가 지정한 경우만 붙인다
- **draft 여부를 임의로 정하지 않는다.** 미완성 작업이라 판단되면 draft로 할지 묻는다
- **여러 remote가 있으면 대상을 추측하지 않는다.** 어느 저장소에 PR을 열지 확인한다
